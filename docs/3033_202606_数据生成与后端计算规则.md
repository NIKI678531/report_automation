# 月度基金评论通用数据识别、计算与图表快照规则

> 黄金样例：`3033 Monthly Commentary - 30 June 2026_LCD.pdf`（报告日 `2026-06-30`）。  
> 文档用途：定义多基金可复用的数据识别、字段映射、计算、质量检查、血缘和图表快照绑定规则；3033 仅作为验证样例。  
> 上位规范：`docs/spec/月度基金评论报告生成系统_Agent执行规格书_V2.1.md`。冲突时以上位规范为准。

## 1. 适用范围与核对结论

系统必须围绕**逻辑数据集和规范字段**工作，而不是围绕文件名、工作表名、固定列号或基金代码工作。

- 文件名、sheet 名和单元格坐标只能作为某个 `mapping_profile` 的示例指纹，不能成为计算规则。
- 同一功能可由 CDB 视图、CSV 或 XLSX 提供，只要映射后满足相同的规范字段契约。
- 一个物理工作簿可以识别出多个逻辑数据集；一个逻辑数据集在同一快照中只能有一个生效来源。
- 产品代码、基准代码、币种、时区、模块开关、显示名称和格式规则来自有效期化配置，不在解析器、公式或模板中写死。
- 自动识别只提出确定性候选。无表头、重复表头、单位不明或多个候选同分时，必须展示预览并由用户确认，禁止静默猜列。
- PDF 只用于视觉和黄金回归，不是生产事实来源；不得从 PDF 反向抄数补齐缺失数据。

本次实际文件核对结果：

- 指数 CSV 有 30 条唯一成份股；Bloomberg 工作簿 M5:M34 有 30 条唯一证券代码，集合 30/30 完全一致。
- Bloomberg B:E 与 G:J 是两组完全重复的收益数据，只能映射其中一组，不能重复导入。
- 旧 `Sheet1` 只与当前成份股集合重合 13/30，且提供 GICS 而非 HSICS，不能生成本期行业图。
- CSV 权重合计为 `99.999999999%`；按 `Industry` 聚合可精确复核 PDF 的四个行业。
- HSICS Excel 的说明和汇总数据是 105 个子行业，而报告日有效 PDF 说明为 112 个子行业；该 Excel 不能单独证明完整的报告日有效 taxonomy，只能作为待审批映射参考。
- 当前附件没有基金官方 Total Return 日序列、AUM 日值、每日成交额和指数事件，相关结果不能从现有 Excel 独立复算。

通用链路：

```text
物理来源(CDB/CSV/XLSX)
  -> 数据集识别
  -> 版本化字段映射
  -> 规范化逻辑数据集
  -> 跨表连接与质量检查
  -> 不可变 DataSnapshot
  -> 版本化 MetricValue
  -> 图表/表格/脚注 ModuleSnapshot
  -> HTML/PDF/DOCX
```

## 2. 功能与逻辑数据集对应表

“用哪张表”是逻辑数据集选择问题。物理文件和工作表只负责提供字段，计算引擎只读取规范数据集。

| 功能/输出 | 必需逻辑数据集 | 最小规范字段 | 识别提示与当前样例 | 缺失处理 |
| --- | --- | --- | --- | --- |
| 报告标题、产品/基准绑定 | `product_master` | `product_code, ticker, product_name, constituent_index_code, benchmark_instrument_code, currency, timezone, valid_from, valid_to` | 通常来自产品配置/CDB；3033、HSTECH、HSTECHN 只是三个不同角色的示例 | 阻断整份报告 |
| Historical Performance | `total_return_series` | `instrument_code, trade_date, total_return_value, series_type, currency, source` | 识别“工具 + 日期 + Total Return 值”的长表；当前 Excel 只有基准期间回报，没有基金日序列 | 基金或基准端点缺失则该周期 N/A；关键周期阻断 |
| Constituents Performance | `constituent_snapshot` + `constituent_period_return` | 证券代码、名称、价格、权重、币种、as-of；各周期起止日和回报 | 示例：CSV 静态字段与 Bloomberg B:E 回报按证券代码连接 | 连接非一对一、权重不平或关键字段缺失即阻断 |
| Top N Constituents | `constituent_snapshot` + `security_alias`（可选） | `security_code, weight, report_display_name` | 从成份股快照按权重排序；N 和营销显示名来自模板/别名配置 | 权重缺失阻断；显示名可回退规范名并告警 |
| Index Sectors Breakdown | `constituent_snapshot` + `industry_master` | `source_industry_code, weight`；HSICS `code, level, name, valid_from, valid_to` | 示例：CSV `Industry` + 有效 HSICS master；不得使用旧 GICS `Sheet1` | 任一证券未映射或行业勾稽失败即阻断 |
| Top/Bottom Performers | `constituent_period_return` + `constituent_snapshot` | `security_code, return_1m, weight` | 示例：Bloomberg 1M 回报与 CSV 权重连接 | 排除 N/A；有效记录少于配置数量时显示全部并告警 |
| AUM | `fund_kpi_daily` | `product_code, observation_date, metric_code=AUM, value, currency, unit, source` | 当前附件无此表；可由 CDB 或等价上传表提供 | 阻断 Portfolio Analysis 的 AUM 行 |
| Average Daily Turnover | `fund_kpi_daily` + `trading_calendar` | 每日 `DAILY_TURNOVER`、币种、单位、日期、应有交易日 | 当前附件无此表；按报告月识别日频记录 | 覆盖率低于阈值时阻断 |
| Number of Holdings | `constituent_snapshot` | `security_code, weight` | 统计 `weight > 0` 的唯一证券，不读取预期数量作为结果 | 快照缺失即阻断 |
| Next Rebalancing Date | `index_event` | `index_code, event_type, effective_date, source` | 当前附件无此表；官方事件优先于日期算法 | 不得推测；按模板策略隐藏或阻断 |
| 数据脚注 | 上述数据集的 `lineage` | 来源、as-of、period_start/end、币种、单位、映射/公式版本 | 根据实际生效记录生成，不复制 PDF 文本 | 来源或期间不明时阻断终稿 |
| Company News | `security_master` + `news_item` | 主体、证券映射、URL、来源、发布时间、标题/摘要 | 与计算表解耦，使用同一生效成份股集合匹配主体 | 无 URL、主体不匹配或日期越界时不可入选 |

建议来源优先级：CDB 版本化只读视图 > 经审批的完整逻辑数据集覆盖文件 > 黄金 fixture。同一数据集不得逐行或逐字段混合来源。

## 3. Excel/CSV 自动识别与字段映射

### 3.1 识别流程

1. **盘点来源**：读取全部工作表、可见范围、候选表头行、公式缓存值和 checksum；不得默认使用第一个 sheet。
2. **规范化表头**：执行 Unicode NFKC、去首尾空格、合并换行/连续空格、大小写折叠和标点标准化；原始文本保留用于血缘。
3. **匹配字段别名**：用版本化 alias dictionary 将物理表头映射为规范字段。
4. **识别数据集指纹**：按必要字段覆盖、数据类型、行级模式、关键值域和主键特征为每个 sheet 评分，不按 sheet 名评分。
5. **处理无表头字段**：只能使用已审批 layout profile，或与另一权威数据集做键集合对账后由用户确认；不得只凭列号猜测。
6. **确认单位和日期**：单位来自表头、单元格格式、来源契约或映射配置；不得按数值大小猜百分数/比例。日期必须映射到明确业务语义。
7. **展示映射预览**：显示原始字段、规范字段、转换、单位、样例值、空值率、唯一率、候选 sheet 和置信状态。
8. **保存配置**：确认后保存 `mapping_profile_id + mapping_version`，按供应商/导出格式复用，不按具体文件名或基金代码复用。
9. **失败关闭**：新增/缺失列、表头漂移、多个候选同分、单位变化或关键校验失败时置为 `NEEDS_MAPPING` 或 `REJECTED`，不得退回固定列号继续生成。

只有全部必需字段唯一映射、单位明确、主键校验通过、日期有效且候选数据集唯一时，才可自动接受。

### 3.2 各逻辑数据集识别指纹

| 逻辑数据集 | 必需字段指纹 | 行级/值域检查 | Example 提示 |
| --- | --- | --- | --- |
| `product_master` | 产品代码、成份股指数代码、收益基准工具代码、币种、有效期 | 产品 + 有效期唯一；两个指数角色分别非空 | 可提供标准模板；不要求工作表叫 Product |
| `total_return_series` | instrument、date、TR value、series type | `TR > 0`；instrument + date 唯一；日频 | 示例表头：`Ticker, Date, Total Return, Series Type` |
| `constituent_snapshot` | as-of、index、security、weight、price/currency | index + as-of + security 唯一；权重可勾稽 | 当前 CSV 的 `Prod Dt, Idx Cde, Lcal Cde, Pct Idx Wgt, Cls Price` |
| `constituent_period_return` | security、period code、start/end、return、source | security + period 唯一；日期区间一致 | 当前 Bloomberg 工作簿需组合日期行、收益表头和无表头代码列 |
| `industry_master` | taxonomy/version/effective date、level/code/name | 代码层级唯一；父子关系完整 | 当前 HSICS 汇总版式需向下继承父级，但版本信息不足 |
| `fund_kpi_daily` | product、date、metric code、value、currency/unit | product + date + metric 唯一 | 宽表 AUM/Turnover 可在映射阶段转成长表 |
| `trading_calendar` | market、date、is_trading_day | market + date 唯一 | 不以“有成交额记录的日期”反推应有交易日 |
| `index_event` | index、event type、effective date、source | index + type + date 唯一 | 示例事件类型 `REBALANCE` |
| `security_alias` | security、alias type/value、有效期 | 同一类型有效期不得重叠 | 用于报告营销全称和新闻主体匹配 |

### 3.3 映射配置模型

业务代码只引用逻辑数据集和规范字段。映射配置至少包含：

```yaml
mapping_profile_id: vendor_export_family_v1
dataset_type: constituent_period_return
source_family: vendor_or_cdb_view
semantic_metadata:
  unit_source: explicit
  taxonomy: null
sheet_selector:
  required_field_aliases: [return_1m, return_3m, return_6m, return_ytd]
  minimum_required_coverage: 1.0
header_selector:
  mode: scan_and_match
field_map:
  security_code: {source: confirmed_column, transform: normalize_security_code}
  return_1m: {source: matched_header, unit: PERCENT}
  return_3m: {source: matched_header, unit: PERCENT}
  return_6m: {source: matched_header, unit: PERCENT}
  return_ytd: {source: matched_header, unit: PERCENT}
join_keys: [security_code]
mapping_version: 1
```

`source: confirmed_column` 表示该导出格式没有可靠表头，首次导入必须确认。profile 可记录具体列定位作为该**格式版本**的解析细节，但计算代码不得知道它是 M 列，也不得假定 sheet 叫 `Formula`。

### 3.4 通用字段别名与转换

| 规范字段 | 常见候选表头示例 | 转换与校验 |
| --- | --- | --- |
| `as_of_date` | `Prod Dt`, `As Of`, `Effective Date` | 解析 `YYYYMMDD`/Excel 日期；不得晚于报告日 |
| `trade_date` | `Tradate`, `Trade Date`, `Date` | 解析日期；与 as-of 口径不一致时阻断 |
| `index_code` | `Idx Cde`, `Index Code`, `Constituent Index` | 去空格、大写；匹配 `constituent_index_code` 或其有效别名，不与收益基准工具混为一列 |
| `security_code` | `Lcal Cde`, `Code`, `Security Code`, `Local Code` | 文本保存；保留原始值和前导零语义 |
| `ticker` | `Ticker`, `Bloomberg Ticker`, `Instrument` | 分离代码与市场后缀；经 security master 规范化 |
| `name_en` | `Stk Name_E`, `Constituent Name`, `Stock Name` | Unicode 规范化；保留源名称 |
| `name_zh_hant/name_zh_hans` | `Stk Name_TC/SC`, `成份股`, `中文名称` | 不用简繁自动转换覆盖源值 |
| `close_price` | `Cls Price`, `Close`, `Closing Price` | Decimal，必须大于 0；价格币种必填 |
| `currency` | `Lcal Ccy`, `Currency`, `CCY` | ISO 4217；不得默认某一基金币种 |
| `weight` | `Pct Idx Wgt`, `Weighting`, `Weight (%)` | 显式声明 `PERCENT` 或 `RATIO`；统一存 ratio |
| `source_industry_code` | `Industry`, `HSICS Industry Code` | 只有来源 profile 明确声明 `taxonomy=HSICS` 时才接受通用表头 `Industry`；文本化并按层级补前导零 |
| `source_sector_code` | `Sector`, `HSICS Sector Code` | 仅作层级校验/血缘，不替代顶级行业聚合键 |
| `return_1m/3m/6m/ytd` | `1-month return (%)`, `1M Return`, `YTD回報 (%)` | 显式单位；保存 ratio、起止日、series type 和 source |
| `total_return_value` | `Total Return`, `TR Index`, `TR Value` | Decimal 且大于 0；用于计算期间回报 |
| `metric_code/value` | `AUM`, `Daily Turnover`, `Metric/Value` | 转成长表；币种、单位和观察日期必填 |

```text
weight = Decimal(weight_percent_raw) / 100
return_value = Decimal(return_percent_raw) / 100
```

不得按数值大小猜单位。例如 `0.234770787%` 与 ratio `0.234770787` 的业务含义相差 100 倍。

### 3.5 当前样例逐字段核对

坐标只属于本次样例 mapping profile，不是通用计算规则。

| 规范字段/用途 | 当前样例来源 | 核对结果 | 通用处理 |
| --- | --- | --- | --- |
| `as_of_date/trade_date` | CSV `Prod Dt/Tradate` | 均为 20260630 | 按别名识别；两者冲突时阻断 |
| `index_code` | CSV `Idx Cde=HSTECH` | 可直接映射 | 对应 `constituent_index_code`；历史收益基准 `HSTECHN` 另存为 `benchmark_instrument_code` |
| `security_code` | CSV `Lcal Cde`；Bloomberg M5:M34 | 30/30 精确连接；M 列无表头 | CSV 按表头识别；M 列首次通过 layout profile 确认 |
| `ticker` | Bloomberg A5:A34 | 可解析 `<code> HK Equity` | 用 security master 交叉核验 |
| `name_en/name_zh_hant` | CSV `Stk Name_E/TC`；Bloomberg N/O | 可映射；N/O 无表头 | 源名称并存；显示名由有效期化别名决定 |
| `close_price/currency` | CSV `Cls Price/Lcal Ccy` | 可直接映射 | Decimal + ISO 币种 |
| `weight` | CSV `Pct Idx Wgt` | 原始单位为百分数；合计 99.999999999% | `unit=PERCENT` 后除以 100 |
| `source_industry_code/source_sector_code` | CSV `Industry/Sector` | 顶级 HSICS/板块代码可直接映射 | 顶级行业用于图表；板块只作校验和血缘 |
| `period_end` | Bloomberg A2 | 20260630 | 校验不晚于报告日 |
| 各周期 `period_start` | Bloomberg B2:E2 | 20260529/20260331/20251231/20251231 | 分周期保存，不从标题反推 |
| 成份股期间回报 | Bloomberg B5:E34 | 与 PDF 一致；G:J 与其完全重复 | 只导入一组，单位 PERCENT 后除以 100 |
| 基准期间回报 | Bloomberg A35 + B35:E35 | `HSTECHN Index` 可复核 | 作为 BENCHMARK 期间回报，不能替代日频 TR 序列 |
| 非目标指数回报 | Bloomberg A36 + B36:E36 | `HSI Index` 本报告未使用 | 仅当产品配置绑定该基准时启用 |
| 工作簿 A1 日期 | Bloomberg A1=2026-07-15 | 语义未确认且晚于报告日 | 只保留原始元数据，不得当作 as-of/period end |
| HSICS 层级 | HSICS 汇总版式 A:H | A/B/C、D/E、F/G、H 分别为三层代码/名称和定义 | 通过字段组识别并向下继承父级，不依赖 sheet 名 |
| GICS 行业 | Bloomberg `Sheet1.GICS_SECTOR_NAME` | 仅重合当前证券 13/30，taxonomy 错误 | 不得映射为 `hsics_industry_code` |
| 基金 TR 日序列 | 当前附件无 | 无法复算基金历史表现 | 必须提供 `total_return_series` |
| AUM/每日成交额 | 当前附件无 | 无法复算两个金额指标 | 必须提供 `fund_kpi_daily` |
| 下一次再平衡事件 | 当前附件无 | PDF 日期不能作为事实表 | 必须提供 `index_event` 或按策略隐藏 |

规范化连接覆盖率由实际成份股数量决定，不固定为 30：

```text
joined_count == unique_constituent_count
missing_return_codes == empty
unexpected_security_codes == empty
```

基准/其他指数记录应先按 `instrument_type` 分流，不计为 unexpected security。

## 4. HSICS 行业映射与图表快照

### 4.1 字典解析与有效版本

HSICS 标准代码宽度为 Industry 2 位、Sector 4 位、Subsector 6 位。Excel 把 `00`、`0010` 读成数字时会丢前导零，必须按层级恢复并按文本保存。

```text
industry_code  = zfill(raw_industry_code, 2)
sector_code    = zfill(raw_sector_code, 4)
subsector_code = zfill(raw_subsector_code, 6)
```

当前 HSICS 汇总版式在父级相同的后续行留空。解析器应在同一层级块内向下继承 Industry/Sector，不得跨越新 Industry 或文件边界继承。

工作表候选必须能映射三层代码和名称、父子前缀一致、层级代码唯一。若多个 sheet 满足，选择经元数据确认且报告日有效的版本，不按名称 `All`、sheet 顺序或“最新”字样猜测。

`industry_master` 至少保存：

```text
taxonomy, version, level, code, parent_code, name_en, name_zh,
valid_from, valid_to, source, source_record_key, checksum
```

有效版本条件：

```text
taxonomy == "HSICS"
and valid_from <= report_date
and (valid_to is null or report_date <= valid_to)
```

同一代码在报告日匹配 0 个或多个版本都阻断。源文件没有机器可读有效期时，上传者必须填写并由 Data Steward 确认。

本次 PDF 明确区分有效至 2026-09-06 的 112 子行业版本和 2026-09-07 起的 114 子行业版本；当前 Excel 自述 105 个子行业。因此：

- 2026-06-30 应选择有效至 2026-09-06 的正式版本；
- 当前 Excel 可辅助核验顶级代码和名称，但不能作为完整正式 master 直接发布；
- 在取得与 PDF 版本一致的 CDB/官方字典前，完整 taxonomy 导入应阻断并记录版本冲突。

### 4.2 成份股映射与聚合

优先读取 `source_industry_code`。若来源只给 Sector/Subsector，允许通过有效字典逐级解析父级；taxonomy 不是 HSICS 时，不因名称相似自动转换。

```text
effective_industry = industry_master.require_effective(
    taxonomy="HSICS",
    source_code=constituent.source_industry_code,
    report_date=report_date,
).top_level_parent

industry_weight[industry_code] = SUM(
    constituent.weight
    for constituent in active_constituents
    if constituent.effective_industry_code == industry_code
)
```

- 聚合键是顶级 HSICS Industry，不是 CSV `Sector` 或 GICS。
- 映射覆盖率必须为 100%；未映射项不得归入未声明的 `Other`。
- 行业总权重与证券总权重差不得超过 0.01 个百分点。
- 使用未舍入 Decimal 聚合，标签才按展示配置舍入。
- 零权重行业默认不进入 series 或图例。
- 图例顺序和颜色来自版本化模板配置，不依赖数据库顺序或计算函数硬编码。

3033 黄金样例：

| `50` | Financials | 0 | 0% | 不显示 |
| `70` | Information Technology | 11 | 49.266295559% | 49.3% |

## 5. 各报告模块通用计算规则

### 5.1 Historical Performance

产品和基准由报告日有效的 `product_master` 绑定。生产来源是双方官方 `total_return_series`，且使用共同交易日起止点、相同 `series_type=TOTAL_RETURN` 和可比较币种定义。

| 周期 | 通用起点规则 | 3033 样例起点 | 样例终点 |
| --- | --- | --- | --- |
| 1M | 截止日前 1 个自然月目标日之前或当日的最近共同交易日 | 2026-05-29 | 2026-06-30 |
| 3M | 截止日前 3 个自然月目标日之前或当日的最近共同交易日 | 2026-03-31 | 2026-06-30 |
| 6M | 截止日前 6 个自然月目标日之前或当日的最近共同交易日 | 2025-12-31 | 2026-06-30 |
| YTD | 上一自然年最后一个共同交易日 | 2025-12-31 | 2026-06-30 |

```text
period_return = TR(period_end) / TR(period_start) - 1
```

直接上传期间回报时，必须同时映射 `period_start, period_end, series_type, source`，不能只凭 `1M` 列名推测日期。当前 Bloomberg 基准行可作对账，但不能补齐缺失的基金日序列。输出名称来自产品配置，不固定为 3033/HSTECHN。

### 5.2 Constituents Performance

| 报告列 | 规范字段 | 当前样例 |
| --- | --- | --- |
| Stock Code | `constituent_snapshot.security_code` | CSV `Lcal Cde` |
| Stock Name | `report_display_name`，回退 `name_en` | Bloomberg N 列或经批准别名 |
| Closing Price | `close_price + currency` | CSV `Cls Price + Lcal Ccy` |
| Weighting | `weight` | CSV `Pct Idx Wgt` |
| 1M/3M/6M/YTD | `constituent_period_return.return_value` | Bloomberg B:E |

```text
JOIN ON normalized security_code
ORDER BY weight DESC, security_code ASC
```

连接覆盖必须等于生效成份股集合大小；回报文件中的指数行和额外证券不得扩充成份股集合。证券上市日晚于周期起点或端点缺失时显示 N/A 并保存 `missing_reason`，不能用 0 代替。

下一次再平衡日期来自 `index_event`。3033 样例的 2026-09-04 不在附件数据中；“季度首个星期五”只能作为说明，不能替代官方事件。

### 5.3 Top N Constituents

```text
ORDER BY weight DESC, security_code ASC
LIMIT template.top_constituent_count
```

N 来自模板配置，3033 示例为 10。少于 N 只时显示全部并告警。营销全称来自有效期化 `security_alias`，不得写在模板里。

3033 样例前十代码：`981, 9999, 700, 3690, 1211, 1810, 9988, 1347, 9888, 9618`。

### 5.4 Index Sectors Breakdown

按第 4 节映射顶级 HSICS 后聚合 `weight`。3033 样例显示 1 位小数；其他基金/模板使用各自版本化格式配置。合计容差在舍入前检查。

### 5.5 Top/Bottom Performers

榜单基于规范化 1M 回报，并连接权重和显示名。数量来自模板配置。

```text
top_selected = ORDER BY return_1m DESC, weight DESC, security_code ASC
               LIMIT template.performer_count

bottom_selected = ORDER BY return_1m ASC, weight DESC, security_code ASC
                  LIMIT template.performer_count
```

“选出最差 N 只”和“页面展示顺序”必须分开。3033 PDF 将 Bottom 3 从较低跌幅排到最大跌幅，因此：

```text
bottom_display = ORDER bottom_selected BY
                 return_1m DESC, weight DESC, security_code ASC
```

若模板希望最差者优先，可把 display direction 配置为 ASC，但不得改变入选集合。标题月份由 `report_date` 按语言格式化，脚注来自实际 1M 起止日。

3033 样例 Top 展示顺序为 1347、2513、981；Bottom 入选排序为 100、285、2382，PDF 展示顺序为 2382、285、100。

### 5.6 Portfolio Analysis

#### Asset Under Management

```text
aum = unique fund_kpi_daily[
  product_code=report.product_code,
  metric_code="AUM",
  observation_date=report.effective_date
]
display_value = convert_unit(aum.value, aum.unit, template.aum_display_unit)
```

币种、原始单位和显示单位必须显式保存，避免已是 million 的值再次除以一百万。默认不允许静默取最近旧值；如产品确有非交易日回退规则，必须在产品配置中版本化并在脚注披露。3033 PDF 值为 `HKD 67,536.55 million`，但附件没有底层记录可复算。

#### Average Daily Turnover

```text
expected_days = trading_calendar.trading_days(report_month, market)
observations = valid fund_kpi_daily rows[
  product_code=report.product_code,
  metric_code="DAILY_TURNOVER",
  observation_date in expected_days
]
coverage = COUNT(DISTINCT observations.date) / COUNT(expected_days)
average_daily_turnover = SUM(observations.value) / COUNT(observations)
```

重复日期先阻断，不得重复计入分母。覆盖率基线为 95%；低于阈值阻断，未满 100% 时告警。3033 PDF 值为 `HKD 12,882 million`，附件没有每日序列可复算。

#### Number of Holdings

```text
number_of_holdings = COUNT(DISTINCT security_code WHERE weight > 0)
```

结果来自生效快照。产品配置中的预期数量只用于独立 QC，不能作为结果。3033 样例为 30。

### 5.7 脚注生成

动态脚注由血缘生成，不由模板保存整段文本：

```text
source_label <- lineage.source_display_name
as_of <- effective record date
period_start/end <- MetricValue period
coverage <- KPI observation coverage
taxonomy_version <- industry mapping version
```

同一脚注涉及多个来源时逐项列出，不得用一个供应商覆盖所有指标。来源或日期不明时阻断终稿。

### 5.8 表格与模块快照

每个输出组件生成不可变 `module_snapshot`：

```text
module_code, snapshot_id, metric_value_ids[], source_dataset_ids[],
formula_version, mapping_version, template_version,
rows/series, display_format, footnote_binding_ids[], input_checksum
```

- Historical Performance 绑定基金/基准期间回报 MetricValue。
- Constituents 表绑定规范化连接结果，不在模板中再次读取 Excel。
- Top N、Top/Bottom 和行业图绑定同一成份股快照与回报版本。
- Portfolio 绑定 AUM、成交额平均值、覆盖率和持仓数 MetricValue。
- 数据或映射变化生成新 snapshot/MetricValue/module snapshot；旧成品保持原绑定。
- 三种输出格式只消费 module snapshot，不自行重算、重新排序或从显示字符串提取数值。

## 6. 展示名、精度与舍入

- 所有金额、权重和回报在计算层使用 Decimal；浮点数不得作为权威类型。
- ratio 统一保存为小数，例如 10.15% 保存为 `0.1015`。
- 精度来自版本化 `display_format_profile`。3033 示例：回报和 Top N 权重 2 位、行业图 1 位、AUM million 值 2 位、成交额 million 值 0 位。
- 使用 `ROUND_HALF_UP`，只在最终展示层舍入。
- 证券代码、SEDOL 和 ticker 按文本保存，不因数值转换丢前导零。
- 源名称、规范名称和营销显示名分字段保存，并记录别名版本及有效期。
- `raw_value`、API 数值和表格计算值保留原始精度及单位；`display_value` 不可回流计算。

## 9. 必须执行的质量检查

| ID | 检查 | 通用标准 | 失败处理 |
| --- | --- | --- | --- |
| MAP-001 | 数据集识别唯一 | 每个必需逻辑数据集恰有一个候选/已确认映射 | NEEDS_MAPPING，禁止生成 |
| MAP-002 | 必需字段完整 | 所有规范必需字段唯一映射 | 阻断 |
| MAP-003 | 单位明确 | 百分数/ratio、币种、金额单位均来自契约 | 阻断，不得猜测 |
| MAP-004 | Schema drift | 表头、类型、布局符合已审批 profile | 创建新 profile 或拒绝 |
| CFG-001 | 产品与指数角色 | 成份股指数和收益基准工具分别绑定且有效 | 阻断 |
| DAT-001 | 证券唯一 | index + as-of + security 唯一 | 阻断 |
| DAT-002 | 日期一致 | 数据日期不晚于报告日；期间完整 | 阻断 |
| JOIN-001 | 成份股/回报连接 | `joined_count == unique_constituent_count`，无缺失/额外证券 | 阻断 |
| CAL-001 | 权重合计 | 100% ± 0.01 个百分点 | 阻断 |
| IND-001 | HSICS 版本唯一有效 | 报告日恰有一个有效版本 | 阻断 |
| IND-002 | 行业覆盖 | 100% 成份股映射到顶级 HSICS | 阻断行业图和终稿 |
| IND-003 | 行业勾稽 | 行业合计与证券合计差 ≤ 0.01 个百分点 | 阻断 |
| RET-001 | Return 类型 | 官方 Total Return 或经批准的期间回报覆盖 | 阻断相应模块 |
| RET-002 | 共同端点 | 基金/基准同起止日、series type、币种定义 | 阻断历史表现 |
| RET-003 | N/A 语义 | 缺失为 N/A，真实零回报为 0 | 错误替代即阻断 |
| KPI-001 | AUM 时点/单位 | 报告日有效单点，币种和单位明确 | 阻断 AUM 行 |
| KPI-002 | 成交额覆盖 | 唯一日记录；交易日覆盖率 ≥ 配置阈值（基线 95%） | 低于阈值阻断 |
| SORT-001 | 稳定排序 | 排名与 display order 均有显式 tie-breaker | 测试失败 |
| OUT-001 | 模块快照勾稽 | 表格/图表 raw values 与 MetricValue 一致 | 阻断渲染/终稿 |
| OUT-002 | 跨格式一致 | HTML/PDF/DOCX 使用同一 module snapshot | 阻断发布 |
| FOOT-001 | 脚注一致 | 来源、as-of、期间和覆盖率来自血缘 | 阻断终稿 |

产品的预期持仓数量可以作为额外 QC，但不能成为全局规则，也不能替代实际计数。

## 10. 当前样例冲突与处理决定

| 冲突 | 实证 | 处理决定 |
| --- | --- | --- |
| 第 3 页脚注日期错误 | PDF 写 12 日；Bloomberg A2:E2 是 30 日结束、29/31/31/31 日开始 | 用实际 period 字段自动生成脚注 |
| Top/Bottom 来源名冲突 | PDF 写 Wind；数值与 Bloomberg B:E 一致 | 使用实际生效 dataset 的 source；不明则阻断 |
| `Sheet1` 不是本期成份股表 | 只与当前集合重合 13/30，权重和分类均旧 | 不参与本期快照 |
| GICS 与 HSICS taxonomy 不同 | `Sheet1` 是 GICS；PDF 行业图是 HSICS 10/23/28/70 | 只按有效 HSICS 聚合 |
| HSICS Excel 版本不足 | Excel 自述 105 子行业；报告日 PDF 版本为 112 | Excel 只作参考；完整 master 等待正式有效版本 |

## 12. 当前实现与目标规则的差距

本文定义目标契约，不代表现有解析器已经全部通用化。当前代码仍有以下落地项：

- `backend/app/domain/ingestion.py` 仍固定识别 `Formula`、`Sheet1` 和具体列号，需改为版本化 mapping profile + 映射预览。
- `index_constituents` 当前只接受固定 CSV 表头；需支持 XLSX/CDB 等价字段和 alias dictionary。
- 当前 `sector_mapping` 读取旧 GICS `Sheet1`；生产行业模块必须切换为报告日有效 HSICS master。
- 当前计算与导入部分仍使用 float；权威金额、权重和回报应全程使用 Decimal。
- 当前行业 series 默认按名称排序；应改为模板配置的 display order/color token。
- 当前 Bottom 列表按最差者优先返回；要匹配 3033 PDF，需单独实现 selection order 与 display order。
- `total_return_series`、`fund_kpi_daily`、`trading_calendar`、`index_event` 和 module snapshot 仍需按本契约接入。
- 多基金扩展应新增产品/模板/映射配置，不复制 3033 parser、fixture 数值或固定工作表规则。
