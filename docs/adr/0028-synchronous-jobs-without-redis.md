# ADR-0028：暂时移除 Redis 和独立 worker

- 后续变更：成品存储、渲染任务及下载流程已由 [ADR-0029](0029-on-demand-report-downloads.md) 覆盖；当前按需生成下载，不依赖对象存储，Secret 为 11 个 key。本记录其余内容保留当时决策背景。
- 日期：2026-09-08
- 状态：已接受（用户要求「redis 可以先去掉，有没有什么依赖」）
- 覆盖：ADR-0026 中的 Celery/Redis 部署拓扑，以及执行规格书 V2.1 的异步任务基线。

检查确认 Redis 只承担 Celery 的 broker/result backend；没有业务缓存、登录 session 或分布式锁依赖。
实际队列任务只有报告成品渲染和翻译，前端查询的 RenderJob / TranslationJob 状态已经存于数据库。
采用已有 EAGER 执行路径，不新增线程后台队列或其他消息系统。

所有环境仅支持 `TASK_MODE=EAGER`，启动时拒绝残留 CELERY 或未知模式。
从运行依赖移除 Celery、Redis 及其专属传递依赖；保留 `app/worker.py` 作为同步调度模块。
调用者没有传入 Session 时，调度函数直接创建并关闭数据库会话，不经过 Celery。
K8s 后端只运行 API 容器，迁移仍由 init container 执行；Compose 删除 redis/worker 服务。
Secret、配置守卫、深健康检查不再要求 Redis。MySQL/TOS、签名密钥和启用的数据来源依赖继续保留。

渲染仍创建任务记录、落库成功/失败状态并复用幂等结果；失败后由用户显式重新生成。
翻译保留数据库原子认领、版本校验和最多三次可重试调用；达到次数限制后落库 FAILED。
HTTP 202 和查询接口为兼容前端保留，但新建任务的响应在执行结束后才返回，不代表后台执行。

## 限制与运维

- 请求线程在渲染／翻译期间被占用；浏览器等待结果，API CPU/内存也承担 Chromium 和 DOCX 工作。
  当前仅适合较低并发；不承诺独立队列的吞吐量、取消、硬超时或自动恢复能力。
- 翻译网关每次超时默认 45 秒，可配置 1–60 秒，最多三次调用。多格式渲染也顺序执行。
  nginx 现有 API 读写超时为 900 秒；宿主平台/外层代理必须允许长请求并按真实负载验证。
  nginx 的超时只限制等待响应，不会中止后端任务。
- uvicorn 优雅退出等待 210 秒，K8s/Compose 的终止宽限 240 秒，给请求完成留出空间；
  这些数值不是任务硬时限，也不能保证进程被强杀、OOM 或超长任务时完成。
- 发布前先停止提交任务，等待旧 worker 的 QUEUED/RUNNING 任务清空，再移除队列服务。
  本次只改本地文件，不删除共享 Redis 实例、不操作真实任务或线上 Secret。
  既有 `.env.<env>` 需手动删除 `REDIS_URL` 行，按新模板保留 13 个 key 后重建 Secret。
- 请求超时或进程重启后先刷新查询状态。翻译沿用四分钟过期检查，可显式重试；
  渲染没有自动恢复，遗留 QUEUED/RUNNING 不会被新 API 接管，需要排查后用新幂等键重新生成。
  不直接改数据库为成功，不把旧队列当作已经处理完毕。

未来需要持续后台执行或提高并发时，另行设计并验证可靠队列、任务版本固定、重试与恢复；
不能只将 TASK_MODE 改回 CELERY。回滚旧镜像也必须同时恢复匹配的 worker、Redis 配置和 Secret。

## 验证

覆盖同步成功/失败落库、翻译重试耗尽与成功、无传入 Session 的调度分支、旧模式启动拒绝、
部署结构及 Secret、健康检查；在干净 Linux 镜像检查依赖与应用导入。结果见 `k8s/VALIDATION.md`。
