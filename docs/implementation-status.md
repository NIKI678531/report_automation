- Microsoft Entra token validation is implemented in `app/core/entra.py`: tenant JWKS with a TTL cache and rate-limited rollover refresh, algorithm pinning that rejects symmetric and `none` algorithms, audience/issuer/expiry/not-before validation with leeway, `oid` preferred over `sub` as the subject, and role plus product scope read from configurable claims. `AUTH_MODE=ENTRA` ignores identity headers entirely, and a missing PyJWT fails startup rather than the first authenticated request.
- One authorization boundary for the whole API, as a pure ASGI middleware so the principal reaches the service layer and the audit trail through a context variable rather than an argument on every signature. VIEWER is read-only everywhere, finalize is REVIEWER/ADMIN, catalog / industry-master / mapping-profile writes are ADMIN, and product scope filters rows so an out-of-scope report is absent rather than refused. Health is exempted by exact path match, and CORS is outermost so a browser can read a denial.
- Security headers on every response including hand-built denials: `nosniff`, `DENY`, `no-referrer`, `same-origin`, and a Content-Security-Policy chosen by content type — `default-src 'none'` for JSON and downloads, a document policy for the HTML preview that permits inline style, `data:` images and fonts, and no script at all. Jinja autoescape is unconditional; suffix-based `select_autoescape` left `*.html.j2` unescaped.
- Startup configuration guard (`Settings.deployment_problems()`): a deployed process refuses to boot with the repository's default or a short `DOWNLOAD_SECRET`, an unknown `AUTH_MODE`, a missing Entra audience/issuer/JWKS, a symmetric or `none` algorithm, `ALLOW_TESTING_LANE` enabled, a SQLite `DATABASE_URL`, or artifacts still configured to land on container-local disk. Every reason is logged by name. Compose secrets are `${VAR:?message}` references with `.env.example` templates at the repository root and under `backend/`.
- Artifacts are written through an object-storage port with two backends: `LOCAL` under `var/output` for workstations and `S3` for any S3-compatible bucket (Volcengine TOS, MinIO, AWS S3), selected by `STORAGE_BACKEND`. The deployment provides no persistent volume, so `STORAGE_BACKEND=LOCAL` outside `AUTH_MODE=LOCAL` is a startup refusal of the same class as SQLite, and a backend nothing implements is refused rather than falling through to local disk — that silent fallback made an environment look configured while storing nothing durable. The download route streams from the port instead of reading a path, and an artifact whose object has vanished is a 404 `ARTIFACT_CONTENT_MISSING` rather than a 500. Chromium and python-docx render through a real path, so on a remote backend the local copy is deleted once the object is stored; a worker that kept one per render would fill its own writable layer.
- Uploads are bounded while streaming rather than after buffering, per file, per batch file count and per batch total, and artifact downloads are HMAC-SHA256 signed, TTL-bound and tied to the requesting subject. Storage keys are untrusted on the way back in: the local backend refuses a key that escapes the storage root, and the S3 backend validates a key segment by segment rather than normalizing it, because a bucket has no filesystem to resolve `..` against and a traversal key simply names a different object.
- MySQL 8 production adaptation: `pool_pre_ping`, `pool_recycle`, sizing and connect timeout for network backends, `charset=utf8mb4` on the connection and `--character-set-server=utf8mb4` on the server, and long-value uniqueness moved onto hash columns so no index key exceeds the InnoDB 3072-byte limit. `backend/tests/test_migrations.py` steps every revision up and down individually, asserts the schema survives a downgrade/re-upgrade, enforces the index-length and declared-length rules from ORM metadata, and runs the whole chain against a real MySQL 8 database when `TEST_MYSQL_URL` is set.
- The frontend surfaces the structured envelope through a typed `ApiError` carrying status, error code, fix hint, request id and findings, with a readable fallback when nginx answers instead of the API. Missing constituent close prices render as `N/A` instead of a fabricated `0.00`.
- CI installs every extra the production image carries (`dev,render,entra,storage`) and runs the migration chain against a real MySQL 8.4 service container on every push, so a broken pin is caught there rather than in the first deployment that sets `AUTH_MODE=ENTRA` or `STORAGE_BACKEND=S3`. The published image installs the same set, so switching either mode is configuration only.
- `scripts/check_deployment.py` is a preflight for an environment: it evaluates the same settings that would refuse startup, then the ones the application only reaches at first use — the database is connectable, at head and entirely utf8mb4; the tenant's key endpoint answers; the artifact bucket is addressable; and with `--token` a real access token resolves to the subject, role and product scope the API will act on. `--env-file` checks the environment a file describes rather than the current one, so a workstation can prove the production configuration clean before anything runs on it. The token is never logged and a non-zero exit means the environment must not serve traffic.
- `docs/entra-setup.md` is the tenant-side runbook: app registration and Application ID URI, the four app-role values, the three supported ways to carry product scope with the consequence of each, the settings to write, and an `error_code` → cause table covering every rejection path in `app/core/entra.py`.
