- Microsoft Entra token validation is implemented in `app/core/entra.py`: tenant JWKS with a TTL cache and rate-limited rollover refresh, algorithm pinning that rejects symmetric and `none` algorithms, audience/issuer/expiry/not-before validation with leeway, `oid` preferred over `sub` as the subject, and role plus product scope read from configurable claims. `AUTH_MODE=ENTRA` ignores identity headers entirely, and a missing PyJWT fails startup rather than the first authenticated request.
- One authorization boundary for the whole API, as a pure ASGI middleware so the principal reaches the service layer and the audit trail through a context variable rather than an argument on every signature. VIEWER is read-only everywhere, finalize is REVIEWER/ADMIN, catalog / industry-master / mapping-profile writes are ADMIN, and product scope filters rows so an out-of-scope report is absent rather than refused. Health is exempted by exact path match, and CORS is outermost so a browser can read a denial.
- Security headers on every response including hand-built denials: `nosniff`, `DENY`, `no-referrer`, `same-origin`, and a Content-Security-Policy chosen by content type — `default-src 'none'` for JSON and downloads, a document policy for the HTML preview that permits inline style, `data:` images and fonts, and no script at all. Jinja autoescape is unconditional; suffix-based `select_autoescape` left `*.html.j2` unescaped.
- Startup configuration guard (`Settings.deployment_problems()`): a deployed process refuses to boot with the repository's default or a short `DOWNLOAD_SECRET`, an unknown `AUTH_MODE`, a missing Entra audience/issuer/JWKS, a symmetric or `none` algorithm, `ALLOW_TESTING_LANE` enabled, a SQLite `DATABASE_URL`. Every reason is logged by name. Compose secrets are `${VAR:?message}` references with `.env.example` templates at the repository root and under `backend/`.
- ADR-0029 replaces persistent finished files with on-demand exports from the finalized version. Each request uses isolated scratch space and removes it after response completion or failure. No S3/TOS client, storage extra, output volume or new RenderArtifact/RenderJob row is required. Source versions and export audit metadata remain in MySQL.
- Uploads are bounded while streaming per file and batch. Download grants bind report, finalized version, format, subject and expiry; the content route rechecks product access and integrity before rendering.
- MySQL 8 production adaptation: `pool_pre_ping`, `pool_recycle`, sizing and connect timeout for network backends, `charset=utf8mb4` on the connection and `--character-set-server=utf8mb4` on the server, and long-value uniqueness moved onto hash columns so no index key exceeds the InnoDB 3072-byte limit. `backend/tests/test_migrations.py` steps every revision up and down individually, asserts the schema survives a downgrade/re-upgrade, enforces the index-length and declared-length rules from ORM metadata, and runs the whole chain against a real MySQL 8 database when `TEST_MYSQL_URL` is set.
- The frontend surfaces the structured envelope through a typed `ApiError` carrying status, error code, fix hint, request id and findings, with a readable fallback when nginx answers instead of the API. Missing constituent close prices render as `N/A` instead of a fabricated `0.00`.
- CI installs every extra the production image carries (`dev,render,entra`) and runs the migration chain against a real MySQL 8.4 service container on every push, so a broken pin is caught there rather than in the first deployment that sets `AUTH_MODE=ENTRA`. The published image installs the same set, so enabling optional Entra is configuration only.
- `scripts/check_deployment.py` is a preflight for an environment: it evaluates the same settings that would refuse startup, then the ones the application only reaches at first use — the database is connectable, at head and entirely utf8mb4; the tenant's key endpoint answers; export scratch space is writable and removable; and with `--token` a real access token resolves to the subject, role and product scope the API will act on. `--env-file` checks the environment a file describes rather than the current one, so a workstation can prove the production configuration clean before anything runs on it. The token is never logged and a non-zero exit means the environment must not serve traffic.
- `docs/entra-setup.md` is the tenant-side runbook: app registration and Application ID URI, the four app-role values, the three supported ways to carry product scope with the consequence of each, the settings to write, and an `error_code` → cause table covering every rejection path in `app/core/entra.py`.

## Incomplete or environment-dependent

- Editorial translation rollout: the approved gateway URL, model and secret must be configured in API and tested using approved non-sensitive samples; no real translation service was contacted. The new migration has passed local schema/upgrade/downgrade checks, but real MySQL concurrency and deployed synchronous request timeouts remain environment gates (ADR-0028). Final merged-worktree verification (2026-09-08): backend 373 passed with two environment skips (HSTECH acceptance input and real MySQL); frontend 103 passed plus production build. All four PDF visual tests pass after the separate ADR-0023 heading-baseline update. The 19 translation tests include actual HTML/PDF/DOCX text and shared-document checksum verification using a mocked translation gateway. No rendering changes belonging to the separate heading task were reverted.
- The live read-only CDB adapter and approved performance/constituent views have been verified for 3033/HSTECH coverage from 2024 through the latest available 2026 observation. Deployment still requires injecting the database secret and TLS configuration through the company secret store.
- The DA-Report source checkout provides the news and market_monthly_turnovers contracts. Production now reads MySQL directly (ADR-0030); the live schema, optional monthly tables and network/SELECT access remain environment checks. UAT/local may still use SQLite snapshots. Production does not require the dump-to-SQLite/object-storage delivery path.
- Microsoft Entra validation is implemented and unit-tested against locally minted RS256 tokens, but it has not been run against the company tenant, which is the one remaining input only your directory can supply: the tenant id, the API's Application ID URI, and the app-role plus product-scope claim assignments. `docs/entra-setup.md` reduces that to a checklist and `scripts/check_deployment.py --token` verifies it in one command.
- Azure OpenAI deployment is unavailable. The current assisted draft is deterministic and MetricValue-bound; DA-Report snapshot news and manual approved news ingestion are implemented.
- Per the user request (ADR-0028), Celery/Redis and the separate worker have been removed. Rendering and translation run synchronously with database job records; durable background execution, queue hard timeouts and restart recovery are not provided.
- Export bytes are no longer archived. Re-downloading preserves source content but may differ after template/font/renderer updates; original historical bytes cannot be recovered through the new API (ADR-0029).
- The migration chain now runs against a MySQL 8.4 service container in CI. It has not been run against a MySQL instance on the development workstation: Docker Desktop is installed there but its Linux engine requires WSL, which is not installed and needs an administrator. Developers can still verify locally by setting `TEST_MYSQL_URL` against any throwaway MySQL 8 schema.
- English, independent Simplified Chinese and independent Hong Kong Traditional Chinese outputs are implemented. A paired bilingual single-file UI/template remains outside the current UI and is retained only as an API/storage compatibility mode under ADR-0021.
- The output passes five-page A4 validation, including page-4 donut/text checks and the independent page-5 disclaimer safe-area check, but the original four report pages do not meet the specification's recommended 0.5% pixel-difference target against the supplied four-page reference PDF. The latest page-4 difference is 12.0464%; evidence is under `var/artifacts/visual/latest/manifest.json`.
- Formal Marketing, Business, Data Steward, Security, and UAT approvals are external gates and have not been claimed.
- The business-approved full CSOP listed-fund CSV has not been supplied. The production catalog therefore contains only the confirmed 3033 baseline; test-only products are never seeded by migrations.
- Page 04 constituent identity can be loaded automatically from the report-month-effective CDB HSTECH view; 1M/3M/6M/YTD returns are loaded from FMP's dividend-adjusted EOD endpoint using each normalized Hong Kong ticker. An explicit constituent CSV remains an override, and provider tests use HTTP mocks without committed credentials.
- Review v3 uses a fixed set of prose blocks in a controlled twelve-column flow, allowlisted paragraph typography, bounded nudges and live paged preview. Product/benchmark and module titles are fixed; Simplified and Traditional Chinese security/industry terminology overrides remain available. Dedicated image/data-table block property editors, paired bilingual block editing and undo/redo history remain outside the current scope.
