## 事实状态与表达边界

- 舆情雷达材料为 **V2 重构计划**。在未补充上线或验收证据前，使用“重构方案”“目标效果”“计划实现”，不写成已经取得准确率提升。

- 市值、现货成交、DEX 流动性、永续成交和 OI 是不同口径，必须并列展示，**不得相加**。
- 所有市场内容均为内部监控与辅助分析，不构成投资建议。

## HTML 设计要求

- 采用 16:9 宽屏画布，建议 `1920 × 1080`；每页只保留一个视觉焦点。
- 颜色、圆角、间距、字体和动效全部引用 `DESIGN.md` / `frontend/src/styles/tokens.css` 中的设计 token，不在组件内硬编码。

- 每页结构固定为：明确标题 + 一句话核心结论 + 3–5 个要点 + 一个主要图示或截图区域。
- 金额、百分比和表格数字使用数字字体 token，并保留口径、来源和时间标签。
- 动效只用于页面进入和流程因果，支持 `prefers-reduced-motion`；不使用循环打字、闪烁或装饰性强动画。

## Page 2｜舆情雷达重构：从“负面情绪”转向“需关注问题”

**页面标签：** `Semantic Triage`

**标题：模型升级不是终点，关键是重构判断逻辑**

**核心结论：** 原链路容易把市场下跌、投资者亏损、方向喊单和纯情绪误判为产品负面；V2 计划引入固定版本 `doubao-seed-2-1-pro-260628`，把入口改为“是否存在需要运营关注的产品问题”。

**左侧｜原有缺陷 `Before`**

- 原负面监控依赖 XLM-R 情绪结果，容易形成“看空 / 亏损 = 产品负面”的误判。
- 情绪强弱不能回答问题是否与交易、跟踪、流动性、披露、费用、派息或服务异常有关。
- 关键词如果过早删除证据，可能错过“被套但无法卖出”等同时包含情绪和真实产品异常的内容。
- 证据上下文、归因口径和失败保护不足时，前端卡片难以解释“为什么需要关注”。
- 界面帮助文案仍残留 SnowNLP 口径，需要与实际链路统一。

**中部｜V2 重构链路 `After`**

1. 拉取限定窗口内 CSOP 产品讨论，回复同时携带父帖上下文。
2. 规范化、去重并保留证据 ID、作者数和出现次数。
3. 后台排除规则只作为模型输入，不再提前物理删除证据。
4. Seed 2.1 Pro 以严格 JSON Schema 输出：
   - `actionable`：需关注的产品问题。
   - `excluded`：正常市场波动、机制预期、个人亏损、喊单或纯情绪。
   - `uncertain`：信息不足，保留诊断而不进入主卡。
5. 对排序靠前的产品做第二轮归因，最多生成 3 个问题话题，并引用真实证据 ID。

**右侧｜目标效果 `Outcome`**

- 主卡由“负面提及”改为“需关注问题”，减少把行情观点当成产品异常的误报。
- 输出问题类型、置信度和原始证据，方便运营人员快速复核。
- 规则可以默认排除，模型仍可救回包含明确异常的混合表达。
- 严格 Schema + Pydantic 二次校验 + 证据 ID 校验，提高输出稳定性与可追溯性。
- 单产品失败不影响其他结果；全部失败时保留最近一次成功快照。

**视觉建议：**

- 使用对照型流程图：
  `XLM-R 情绪分类 → 大量“负面”`  ⟶  `Seed 2.1 Pro 语义判断 → 可行动问题 + 证据`
- 在中央放一个醒目标记：`Sentiment ≠ Product Issue`。
- 页脚标注：`当前口径：重构方案；正式汇报前补充实际开发 / 上线 / 验收状态。`

**建议口播（约 35 秒）：**

> 原来的问题不是模型不够新，而是判断目标本身偏了：看空、亏损或情绪激烈，并不等于产品出了问题。V2 会用固定版本的 Seed 2.1 Pro 做语义判断，把正常市场波动和真正的交易、跟踪、流动性等异常分开，同时保留规则、上下文和真实证据。最终前端只展示需要运营关注的问题，并且能够解释原因、追溯证据，也有失败保护。

## Page 3｜Report Automation：从原始数据到多格式报告的闭环

**页面标签：** `Workflow`

**标题：把月度基金评论报告从“拼文件”变成受控工作流**

**核心结论：** 平台已把数据进入、确定性计算、编辑复核、质量门和多格式交付连接到同一份版本化报告文档中，减少重复复制并保持输出一致。

**工作流：**

1. **Data｜统一数据入口**
   - 按产品和报告日期建立报告。
   - 读取获批的 DA Report 快照，并通过单一 constituent performance 文件补充成分股、权重、行业与区间回报。
   - 产品目录、HSICS 行业分类、数据来源与替换记录均保留版本和 lineage。
2. **Calculate & QA｜后端计算与质量门**
   - 后端确定性计算历史表现、Top / Bottom、行业分布和 Final Analytics。
   - 数据缺失、月份错配、覆盖不足或 AI 数字未绑定时，系统阻止 finalization，而不是静默生成。
3. **Review｜六模块工作台**
   - Review、Historical Performance、Company News、Constituent Performance、Final Analytics、Footnotes & Disclosures 在同一工作台完成。
   - 编辑保存为新的不可变版本，支持复核、追踪与回退，不覆盖历史内容。
4. **Deliver｜一份文档，多种交付**
   - 同一个 finalized `ReportDocument` 生成 canonical HTML、PDF 和可编辑 DOCX。
   - 下载文件带有版本、校验和内容清单，减少跨格式内容漂移。

**效果表达：**

- 将重复复制、手工核对和多版本文件传递，收敛为一条可审计流程。
- 计算逻辑集中在后端，前端负责编辑与复核，避免浏览器端出现第二套口径。
- 自动化不替代 reviewer；它把缺数、错数和不一致更早暴露出来。

  `[[截图占位 3-2：Finalization 与交付——四页报告预览，以及 HTML / PDF / DOCX 下载状态]]`

**截图标注建议：**

- 截图 1 标注：`One workspace / Versioned review / Quality gates`

**建议口播（约 35 秒）：**

> Report Automation 目前已经把月度报告的主流程串起来：数据先进入统一快照，由后端完成确定性计算和质量检查，再在六个模块的工作台里编辑复核，最后从同一份定稿文档生成 HTML、PDF 和 DOCX。它的价值不是取消人工审核，而是减少重复复制，让数字、正文和交付文件都能追溯到同一个版本和数据来源。

## Page 4｜RWA 看板：同时看规模、流动性与风险需求

**页面标签：** `Management Dashboard`

**标题：把一次性 RWA 研究转成可持续更新的管理看板**

**核心结论：** 看板将不追求一个模糊的“RWA 总规模”，而是用三层口径回答管理层最关心的问题：市场有多大、在哪里成交、风险需求集中在哪里。

**首屏结构：**

### 1. Executive KPIs｜四个并列指标

- **Observable Spot Union：** 去重后的可观察现货市值。
- **Adjusted Spot Volume：** 剔除 anomaly / stale 后的现货 24h 成交。
- **All-RWA Perps Volume：** 跨平台 RWA 永续 24h 成交。
- **Visible Perps OI：** 公开可见场所的点时 OI。

以 2026-08-09 快照作页面示例时，可分别显示：`$2.62bn / $209.8mn / $4.44bn / $10.94bn`，并明确标注 `Sunday snapshot` 与来源范围。

### 2. Market Structure｜两张核心图

- **现货场所图：** Top venues 的原始成交 vs 质量调整成交，区分 CEX / DEX，突出异常剔除对排名的影响。
- **永续结构图：** All-RWA vs Stock perps 的成交、OI 与集中度，避免只看高换手而忽略风险存量。

### 3. Drill-down｜三类下钻

- **Issuer families：** Ondo / xStocks / bStocks 的官方产品数、CoinGecko 覆盖、规模和主要分发场所。
- **Venue & product：** CEX / DEX、交易对、流动性核心资产以及 Binance TradFi 合约结构。
- **Data quality：** 数据源、更新时间、覆盖状态、异常剔除、`Available / Partial / Not verified`。

**管理作用：**

- 一屏回答“规模、流动性、风险容量、集中度、数据可信度”五个问题。
- 把原始值和质量调整值同时保留，避免异常报价扭曲管理判断。
- 将现货所有权与永续合成敞口分开，避免把不同经济含义的数据相加。
- 从 Excel 单次快照升级为可按日期比较、可下钻、可设置异常提示的持续监控工具。

**视觉建议：**

- 上方四张 KPI 卡；中部左右各一张主图；下方使用 `Issuer / Venue / Quality` 三个轻量入口。
- 主图默认突出 `Adjusted` 口径，原始值以次级线或浅色柱保留。
- 所有指标卡均显示 `Source / As of / Coverage`，数据缺失显示 `Not verified`，不得显示为 0。

**图示占位：**

`[[RWA 看板线框：四个 KPI + Spot Venue 原始/调整对比 + Perps Volume/OI 结构 + 三个下钻入口]]`

**建议口播（约 35 秒）：**

> RWA 资料已经可以支持一个管理层看板，但关键不是做出一个“RWA 总数”。现货市值、现货成交、DEX 流动性、永续成交和 OI 含义不同，应该并列看。首屏会用四个 KPI 加两张结构图，分别回答规模、交易场所和风险需求，再下钻到发行体系、平台和数据质量。这样可以把一次性 Excel 和报告，逐步变成可持续更新的监控工具。
